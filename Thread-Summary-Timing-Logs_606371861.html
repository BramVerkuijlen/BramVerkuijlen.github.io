Purpose / Overview

Thread Summary Timing Logs provide a detailed overview of server thread execution times within the Content Server. They track:

  • Request timing and processing duration

  • SQL execution times and counts

  • Output generation times

  • Queuing and thread-related delays

These logs are primarily used for:

  • Performance analysis of server requests

  • Detecting bottlenecks or delays in server threads

  • Monitoring SQL activity and query performance

Description / Metric

ID of the thread executing the action

Time spent on SQL queries and number of queries per request

GenerateOutput Time

Time spent generating output

Queue Time / TimingTick

Additional timing metrics indicating request delays

Object ID / Parent ID / Context User Name

Specific object and user context information

Relevance

Thread Summary Timing Logs are highly valuable for performance monitoring and optimizing server behavior.

Aspect

Value

Troubleshooting

★★★☆☆ – Can indicate slow requests but not detailed errors

Functional insight

★★☆☆☆ – Limited to timing per function; no content of execution

Performance metrics

★★★★★ – Core source for timing, SQL, and output metrics

Correlation value

★★★★☆ – Very useful when combined with Thread Logs or Client Logs

Correlation

Thread Summary Timing Logs are most effective when correlated with:

  • Thread Logs – to understand what happened during slow requests
    Thread Logs

  • Web Server Client Timing Logs – to connect backend delays to frontend request timing
    Web Server Client Timing Logs

  • SQL Connect Logs – to link long SQL execution times to connection or query issues
    SQL Connect Logs

Observability Context

  • High-frequency log data – requires aggregation or filtering for dashboards

  • Provides endpoint-specific performance metrics when paired with Function.Action

  • Useful for building p95/p99 request latency metrics and node-level comparisons

  • Excellent candidate for time-series ingestion into monitoring tools

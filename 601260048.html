Monitoring Expansion : Architecture & Data flow

Created by Bram Verkuijlen, last modified on dec 29, 2025

This section describes the architecture of the Monitoring Expansion POC, how telemetry flows between components, and the responsibilities of each component. It includes both metrics and logs and how they are integrated into the overall observability pipeline.

Overview

The architecture is designed around a black-box monitoring approach for OTCM (OpenText Content Management). Since OTCM cannot host native OpenTelemetry agents, all observability data is collected externally:
OpenText Content Server (xECM)

  • Logs from OTCM are collected via file scraping using Fluent Bit.
    Fluent-bit

  • Metrics from the Windows host and API endpoints are collected via OpenTelemetry collectors.
    OpenTelemetry

  • All collectors forward their telemetry to a Central Collector, which aggregates, processes, and exposes data to backend systems.
    Central Collector

  • Prometheus scrapes metrics from the Central Collector, while Loki stores logs.
    Prometheus Loki

  • Grafana visualizes both logs and metrics by connecting to Prometheus and Loki.
    Grafana

Components & Responsibilities

Component

Responsibility

Notes

OTCM (Content Management Server)

Generates logs and exposes API endpoints for availability/performance

Source of all observability data

Windows Host

Provides system-level metrics (CPU, memory, disk, etc.)

Metrics are collected by the Host/System Metrics Collector

Fluent Bit

Reads OTCM logs and forwards to Fluent Bit Logs Collector

Lightweight log shipper

OpenTelemetry Collectors

Collect, process, and forward telemetry

Includes Log Metrics Collector, Fluent Bit Logs Collector, API Collector, Host/System Metrics Collector, Central Collector

Central Collector

Aggregates all telemetry, exposes metrics endpoint, forwards logs to Loki

Single point of truth for metrics and log aggregation

Log Metrics Collector

Extracts metrics from logs and sends to Central Collector

Creates derived metrics from log data

Prometheus

Scrapes metrics from Central Collector for visualization

Can be installed locally or on a separate host

Loki

Stores logs for Grafana dashboards

Receives logs from Central Collector

Grafana

Visualizes logs and metrics

Connects to Prometheus and Loki as data sources

Notes

  • Grafana is optional but recommended for visualization

  • Internal metrics from collectors are forwarded through the Central Collector’s to Prometheus

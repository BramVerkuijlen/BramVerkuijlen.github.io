Monitoring Expansion : Environment Requirements

Created by Bram Verkuijlen, last modified on dec 18, 2025

This page describes the technical environment required to run the Monitoring Expansion – OTCM Observability Proof of Concept.

The requirements are intentionally minimal and reflect the single-VM, Windows-based research setup used during the internship.

Operating System

  • Windows Server or Windows 10 / 11

  • 64-bit architecture

  • Administrator access required

The POC was developed and tested entirely on a Windows VM.
Linux or container-based environments are out of scope for this project.

OpenText Content Management Server (xECM)

  • Product: OpenText Content Management Server (xECM)

  • Version: V24.4

  • Deployment type: Windows-based installation

  • Admin access: Required (for logging and monitoring configuration)

Required OTCM features:

  • Security logging enabled

  • Web Server Client logs enabled

  • Timing logs enabled

  • System Monitoring enabled (TCP push)

Monitoring Components

The following tools are required to run the POC:

Fluent Bit

  • Used for log collection and forwarding

  • Windows binary

  • File-based log scraping and TCP input support

OpenTelemetry Collector

  • Core build (host/system metrics)

  • Contrib build (HTTPCheck, Fluent Bit receiver, log-to-metric processing)

Optional (POC Enhancements)

  • Prometheus – Metrics scraping and storage

  • Loki – Log storage

  • Grafana – Visualization

Prometheus, Loki, and Grafana are not required for data collection itself but are used to demonstrate storage and visualization possibilities.

Hardware Requirements (POC)

Minimum recommended specifications for the VM:

  • CPU: 4 vCPUs

  • Memory: 8 GB RAM (16 GB recommended)

  • Disk:

    • Enough space for OTCM logs

    • Additional space for Loki/Prometheus storage (POC-sized)

Exact requirements depend on log volume and scraping intervals.

Permissions & Access

  • Read access to OTCM log directories

  • Ability to bind to local TCP ports

  • Permission to run background processes or services

  • OTCM Admin Panel access

Tooling & Utilities

  • PowerShell 5.1 or higher

  • Text editor (VS Code or Notepad++ recommended)

  • Git (for accessing configuration repositories)

Assumptions & Constraints

  • Single-machine deployment

  • Localhost-based communication

  • No high availability or failover

  • No production security hardening

These constraints are intentional and align with the research and POC nature of the project.

Notes

  • This project does not require Java agent installation.

  • All components can be started manually or via PowerShell scripts.

  • Windows Services were considered but not implemented within the internship timeframe.

Monitoring Expansion : API Metrics Collector

Created by Bram Verkuijlen, last modified on dec 29, 2025

Collector distribution: OpenTelemetry Collector Contrib
https://github.com/open-telemetry/opentelemetry-collector-contrib

This collector uses the HTTP Check receiver to verify that endpoints of the OTCM system are reachable and returning expected responses. It is primarily used in the POC for monitoring endpoints that do not require authentication.

Use Case

OTCM does not expose native health or performance endpoints for all components.

This collector demonstrates how to:

  • Check availability of critical endpoints (ping and auth endpoints)

  • Measure basic latency and response metrics

  • Integrate endpoint checks into an OpenTelemetry pipeline for centralized monitoring

Currently, the collector focuses on endpoints that do not require authentication.

Design Considerations

  • Only endpoints that work without authentication are used in the POC.

  • Does not transform HTTP responses into business metrics; for this, external tools like the Prometheus JSON exporter would be needed.
    https://github.com/prometheus-community/json_exporter

  • Designed as a Contrib collector to use the HTTP Check receiver.

Limitations

  • Cannot automatically re-authenticate with expired bearer tokens. Middleware or API gateway required for authenticated endpoints.

  • Cannot generate derived business metrics from HTTP responses.

  • Metrics are limited to request/response timing, validation results, and response size.

  • httpcheck.request.duration metric is currently broken in this collector version due to a known bug.
    https://github.com/open-telemetry/opentelemetry-collector-contrib/issues/44729

Receivers

Receivers define how telemetry enters the collector.

receivers:
  httpcheck:
    collection_interval: 10s
    metrics:
      httpcheck.dns.lookup.duration:
        enabled: true
      httpcheck.client.connection.duration:
        enabled: true
      httpcheck.client.request.duration:
        enabled: true
#      httpcheck.request.duration:  # currently broken due to bug https://github.com/issues/44729
#        enabled: true
      httpcheck.response.duration:
        enabled: true
      httpcheck.duration:
        enabled: true
      httpcheck.validation.passed:
        enabled: true
      httpcheck.validation.failed:
        enabled: true
      httpcheck.response.size:
        enabled: true
    targets:
      - endpoint: "http://localhost/OTCS/cs.exe/api/v1/ping"
        method: GET
        validations:
          - contains: "rest_api"
      - endpoint: "http://localhost/OTCS/cs.exe/api/v1/auth"
        method: POST
        body: '{"username": "John Doe", "password": "superFakePassword"}'
        validations:
          - contains: "error"
          - json_path: "$.status"
            equals: "unauthorized"

Explanation

Setting

Purpose

httpcheck

Declares the HTTP Check receiver (Contrib version)

collection_interval

How frequently each target is checked

metrics

Defines which request/response metrics are collected

targets

List of HTTP endpoints to check and associated validation rules

validations

Rules to determine if a request passes (string match or JSON path)

The collector uses the HTTP Check receiver from the Contrib version.
https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/main/receiver/httpcheckreceiver

Exporters

Exporters define where the telemetry is sent.

exporters:
  debug:
  otlp:
    endpoint: "127.0.0.1:8895"
    tls:
      insecure: true

Explanation

Exporter

Purpose

debug

Outputs metrics to console for validation and debugging

otlp

Sends metrics to the Central Collector

Pipelines

Pipelines define how telemetry flows through receivers, processors, and exporters.

service:
  telemetry:
    metrics:
      readers:
        - periodic:
            exporter:
              otlp:
                protocol: http/protobuf
                endpoint: "127.0.0.1:8896"

  pipelines:
    metrics:
      receivers: [httpcheck]
      exporters: [debug, otlp]

Explanation

Pipeline

Purpose

metrics

Collects metrics from the HTTP Check receiver and forwards them to debug output and the central collector

telemetry

Periodically exports internal telemetry to the central collector

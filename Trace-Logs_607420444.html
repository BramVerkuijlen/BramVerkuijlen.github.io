Purpose / Overview

Trace Logs appear to be internal diagnostic or audit logs created by specific features or tests within the Content Server.

They may capture:

  • Stack traces of threads

  • Local variables, arguments, and object references

  • Execution of certain administrative or temporary functions

These logs are inconsistent in format and content, and their origin or purpose may vary depending on server configuration or experimental features.

Key Fields & Metrics

Field

Description / Metric

Thread

Thread identifier performing the action

Depth

Stack depth at the point of trace

Status

Status or error message captured

Frame

Function or feature being executed

ObjRef

Object reference, often internal

Line

Source code line reference (if available)

Args / Local / Stack

Argument, local variables, and stack values at trace point

Other Metadata

May include configuration keys, temporary settings, or feature references

⚠️ Disclaimer: These fields are highly variable and may not be consistently present in every log.

Correlation

  • Occasionally, Trace Logs can provide context for errors seen in Thread Logs or Security Logs, but reliability is low.
    Thread Logs Security Logs

  • They are not typically used in monitoring or production troubleshooting.

Observability Context

  • These logs are mostly experimental or audit-related.

  • High volume or complex stack traces may appear if temporary features are enabled.

  • Use with caution, and filter heavily if attempting analysis.

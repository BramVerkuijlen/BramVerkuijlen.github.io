Monitoring Expansion : Fluent Bit Logs Collector

Created by Bram Verkuijlen, last modified on dec 29, 2025

Collector distribution: OpenTelemetry Collector Contrib
https://github.com/open-telemetry/opentelemetry-collector-contrib

This configuration is for the Fluent Bit Logs Collector used in the Monitoring Expansion POC.
It receives logs forwarded by Fluent Bit, performs minimal transformation, and routes the logs to:

  • The Central Collector for storage and visualization

  • The Log Metrics Collector for log-derived metrics

For details about individual log formats and fields, refer to the corresponding log documentation pages.

Design Notes

  • Fluent Bit handles file reading, parsing, and enrichment

  • This collector focuses on routing and normalization

  • Logs are forwarded once and reused for multiple purposes

  • Separation of concerns keeps the system modular and maintainable

Receivers

Receivers define how telemetry enters the collector.

receivers:
  fluentforward:
    endpoint: 0.0.0.0:8006

Explanation

Setting

Purpose

fluentforward

Receives logs using the Fluent Bit / Fluentd forward protocol

endpoint

TCP address and port where Fluent Bit forwards logs

The fluentforward receiver is only available in the OpenTelemetry Collector Contrib distribution.
It is used here to maintain native compatibility with Fluent Bit’s forward output plugin.
https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/main/receiver/fluentforwardreceiver

Processors

Processors modify or normalize telemetry before export.

processors:
  transform:
    log_statements:
      - set(log.body, log.attributes)

Explanation

Setting

Purpose

transform

Applies transformations to incoming log records

set(log.body, log.attributes)

Copies all log attributes into the log body

Why this processor is used

Fluent Bit parses and enriches OTCM logs by adding structured fields as log attributes.
However, when exporting logs to Loki via OTLP, not all attributes are always interpreted or displayed as expected in Grafana.

By copying all log attributes into the log body:

  • All parsed fields become visible in Grafana log views

  • Field-based searching and filtering works more reliably

  • Logs remain readable even when label extraction is limited

  • No log information is lost during export

Exporters

Exporters define where processed logs are sent.

exporters:
  debug:
    verbosity: detailed

  otlp/central:
    endpoint: "127.0.0.1:8895"
    tls:
      insecure: true

  otlp/log-metrics:
    endpoint: "127.0.0.1:8007"
    tls:
      insecure: true

Explanation

Exporter

Purpose

debug

Outputs logs to console for validation and troubleshooting

otlp/central

Sends logs to the Central Collector

otlp/log-metrics

Sends logs to the Log Metrics Collector

This setup allows the same log stream to be reused for both observability and metric extraction.

Pipelines

Pipelines define how logs flow through the collector.

service:
  telemetry:
    metrics:
      readers:
        - periodic:
            exporter:
              otlp:
                protocol: http/protobuf
                endpoint: "127.0.0.1:8896"

  pipelines:
    logs/fluentbit:
      receivers: [fluentforward]
      processors: [transform]
      exporters: [debug, otlp/central, otlp/log-metrics]

Explanation

Pipeline

Purpose

logs/fluentbit

Processes logs received from Fluent Bit and sends the telemetry to the central collector and the log metrics collector

telemetry

Periodically exports internal telemetry to the central collector

This pipeline functions as the handoff point between Fluent Bit and the OpenTelemetry collector architecture.

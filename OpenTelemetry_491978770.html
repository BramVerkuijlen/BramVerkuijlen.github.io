Monitoring Expansion : OpenTelemetry

Created by Bram Verkuijlen, last modified on dec 19, 2025

The OpenTelemetry Collectors form the central processing layer for telemetry in the Monitoring Expansion POC. They receive, process, and export logs and metrics from Fluent Bit.

Purpose

The collectors are responsible for:

  • Receiving logs and metrics from multiple sources

  • Processing and enriching telemetry data

  • Routing telemetry to backend systems (Loki, Prometheus)

This POC uses multiple collectors, each with a focused responsibility for better separation of concerns.

Configuration Overview

Each collector configuration defines:

  • Receivers – How telemetry is ingested (file tailing, TCP, HTTP)

  • Processors – Optional transformations, enrichment, and filtering

  • Exporters – Where telemetry is sent (OTLP, Prometheus, Loki)

  • Service pipelines – Defines the flow of telemetry from receiver → processor → exporter

Active Pipelines

  • Fluent Bit logs – Receives and forwards OTCM logs (thread logs, SQL logs, client logs, security logs)

  • API check metrics – Collects availability metrics (POC)

  • System metrics – CPU, memory, disk, and host metrics

  • Central aggregation – Routes telemetry to backend platforms

  • Log-derived metrics – Extracts metrics from logs for dashboards

Notes & Limitations

  • Multiple collectors used to maintain separation of concerns

  • Contrib receivers are POC-only and not production-ready

  • No authentication is enabled on the collectors

  • Merge collectors or run as Windows Services is recommended for production

Planned Improvements

  • Merge collectors where feasible to reduce resource usage

  • Enable service-based startup for production deployment

  • Harden security and authentication

Monitoring Expansion : HTTPCheck Receiver – httpcheck.request.duration Metric Broken

Created by Bram Verkuijlen on dec 29, 2025

Issue Description
The httpcheck.request.duration metric is currently broken due to a bug in the HTTPCheck receiver. While older documentation still references this metric, it is no longer supported in the latest release.

Other timing metrics from HTTPCheck (e.g., DNS lookup, TLS handshake, client request) are functional.

Example Configuration Snippet

receivers:
  httpcheck:
    metrics:
      httpcheck.dns.lookup.duration:
        enabled: true
      httpcheck.client.connection.duration:
        enabled: true
      httpcheck.tls.handshake.duration:
        enabled: true
      httpcheck.client.request.duration:
        enabled: true
      httpcheck.request.duration:  # <-- Not supported in latest release
        enabled: true
      httpcheck.response.duration:
        enabled: true

Possible Workarounds

  • Use httpcheck.duration instead of httpcheck.request.duration (currently supported).

  • Set disable_keep_alives: true on each endpoint to prevent metrics from defaulting to 0 after the first scrape.

Impact

  • The broken metric prevents accurate monitoring of request durations for HTTP endpoints.

  • Any dashboards or alerts relying on httpcheck.request.duration will display incorrect values or zero.

Next Steps / Notes

  • Monitor updates to the OpenTelemetry Collector HTTPCheck receiver for a fix.

  • Use alternative supported metrics for timing until the issue is resolved.

  • This issue is tracked in GitHub: https://github.com/open-telemetry/opentelemetry-collector-contrib/issues/44729

Monitoring Expansion : Prometheus

Created by Bram Verkuijlen, last modified on dec 29, 2025

This section documents Prometheus as used in the Monitoring Expansion POC. It describes its role in the observability pipeline, the data it collects, how it integrates with other components, and key limitations.

The goal of this part of the documentation is not to explain Prometheus in detail as a monitoring system, but to describe:

  • What data Prometheus collects in this POC

  • How Prometheus is configured

  • How Prometheus integrates with the pipeline

  • Limitations and considerations for future improvements

This documentation is based on the hands-on technical research performed during the internship project.

Purpose

Prometheus is used as the metrics backend in the POC. Its main responsibilities are:

  • Collecting metrics from all OpenTelemetry collectors

  • Collecting internal telemetry from the Central Collector

  • Scraping metrics from Loki for monitoring purposes

  • Providing a Prometheus-compatible endpoint for Grafana dashboards

Prometheus does not generate metrics itself—it only scrapes and stores telemetry from other components.

Context

In this POC, Prometheus is deployed on the same Windows VM as the other components but can also run on a separate host if network access to the collectors and Loki is available.

  • Prometheus Version: 3.8.0

  • Operating System: Windows Server

  • Architecture: Standalone instance scraping the Central collector and Loki

Prometheus interacts with:

  • OpenTelemetry Central Collector – exposes metrics via the /metrics endpoint
    Central Collector

  • Loki – exposes its internal metrics for monitoring
    Loki

Grafana reads from Prometheus to visualize metrics.
Grafana

Key Responsibilities

Prometheus acts as the central metric store:

  • Scrapes metrics from the central collector

  • Scrapes metrics from Loki

  • Provides metrics to Grafana for dashboards

  • Can serve as the basis for alerting (currently not implemented in this POC)

Prometheus does not:

  • Store, process or enrich logs

  • Collect metrics from OTCM directly

  • Provide trace storage

Architecture Role

Prometheus functions as the metrics aggregation and storage layer.

It is positioned downstream of OpenTelemetry collectors, receiving OTLP-to-Prometheus metrics and exposing them via its native /metrics endpoint.
Architecture

Key architectural points:

  • Centralizes all metric data for visualization and alerting

  • Supports long-term storage if configured with retention

  • Provides a single source of truth for metric-based dashboards

Limitations and Constraints

  • Prometheus is configured for local scraping only; remote scraping requires network access and firewall rules

  • Metric retention is default; long-term storage requires additional configuration or remote storage adapters

  • No authentication or TLS is enabled for POC simplicity

  • Alerting configuration is minimal and not actively used

Configuration Overview

The following configuration is used for the POC setup:

# my global config
global:
  scrape_interval: 15s # Set the scrape interval to every 15 seconds. Default is every 1 minute.
  evaluation_interval: 15s # Evaluate rules every 15 seconds. The default is every 1 minute.
  # scrape_timeout is set to the global default (10s).

# Alertmanager configuration
alerting:
  alertmanagers:
    - static_configs:
        - targets:
          # - alertmanager:9093

# Load rules once and periodically evaluate them according to the global 'evaluation_interval'.
rule_files:
  # - "first_rules.yml"
  # - "second_rules.yml"

# A scrape configuration containing exactly one endpoint to scrape:
# Here it's Prometheus itself.
scrape_configs:
  # The job name is added as a label `job=<job_name>` to any timeseries scraped from this config.
  - job_name: "otel-collecto"

    static_configs:
      - targets: ["127.0.0.1:9466","127.0.0.1:8892"]
        labels:
          app: "prometheus"
          source: "otel-col"
    
  - job_name: "loki"
    static_configs:
      - targets: ["127.0.0.1:3100"]

Please refer to the official documentation for more detailed information on how to further configure Prometheus.
https://prometheus.io/docs/prometheus/latest/configuration/configuration/

Global Settings

global:
  scrape_interval: 15s
  evaluation_interval: 15s

  • scrape_interval: Prometheus scrapes metrics every 15 seconds

  • evaluation_interval: Prometheus evaluates rules every 15 seconds

Scrape Targets

Prometheus scrapes metrics from the collectors and Loki:

scrape_configs:
  - job_name: "otel-collector"
    static_configs:
      - targets: ["127.0.0.1:9466","127.0.0.1:8892"]
        labels:
          app: "prometheus"
          source: "otel-col"
    
  - job_name: "loki"
    static_configs:
      - targets: ["127.0.0.1:3100"]

  • otel-collector job: scrapes all OTEL collectors exposing Prometheus metrics

  • loki job: scrapes Loki metrics for monitoring its health and performance

Monitoring Expansion : Quick Start

Created by Bram Verkuijlen, last modified on dec 18, 2025

This page provides a minimal setup guide to quickly start the Monitoring Expansion – OTCM Observability POC on a Windows system.

It assumes that:

  • OpenText Content Management Server (xECM) is already installed

  • All monitoring components are located on a single Windows machine

  • Detailed installation steps are documented separately (GitHub)

Goal

The goal of this quick start is to:

Start the full monitoring stack and verify that logs and metrics from OTCM are being collected successfully.

This guide is intended for:

  • Demonstrations

  • Validation of the POC

  • Development and experimentation

Accessing the POC Repository

This Proof of Concept is maintained in a Git repository.

To obtain the project files:

  1. Ensure Git is installed on the system.

  2. Clone the repository:

git clone https://git.amplexor.com/scm/amnlintern/internship-bram-verkuijlen.git

  1. Place the repository in the desired location:

C:\

The repository contains all configuration files, scripts, and component binaries required to run the POC.

Detailed installation and configuration steps are documented in the repository’s README files.

Prerequisites

Before starting, ensure the following:

  • Windows OS with administrator access

  • OTCM V24.4 is running

  • Required OTCM logging features are enabled

  • Monitoring components are available locally:

    • Fluent Bit

    • OpenTelemetry Collectors

    • (Optional) Prometheus, Loki, Grafana

See: Environment Requirements

Folder Layout

The project is assumed to be located at:

C:\Monitoring Expension\

With the following structure:

Monitoring Expension/
├── Fluent Bit/
├── OpenTelemetry/
├── Prometheus/
├── Loki/
├── start-monitoring.ps1
├── stop-monitoring.ps1

Start the Monitoring Stack

Recommended (POC)

Start all components using the provided PowerShell script:

cd "C:\Monitoring Expension"
.\start-monitoring.ps1

This will start:

  • Fluent Bit (log collection)

  • All OpenTelemetry collectors

  • Loki (log storage)

  • Prometheus (metrics scraping)

Each component runs in the background.

Grafana (Optional Visualization Layer)

Grafana is used in this Proof of Concept to visualize logs and metrics collected by the monitoring pipeline.

Grafana is not included in the startup scripts and must be:

  • Installed separately

  • Configured manually

Deployment Options

Grafana can be deployed in one of the following ways:

Same Windows VM

  • Grafana runs on the same VM as the monitoring components

  • Simplest setup for demonstrations and testing

Separate Host

  • Grafana runs on a different machine

  • Loki and Prometheus must be reachable over the network

  • Better represents a distributed or enterprise-style deployment

Requirements

  • Network access to:

    • Prometheus (metrics)

    • Loki (logs)

  • Compatible Grafana version

  • Appropriate data source configuration

Notes

  • Grafana is used purely for visualization

  • The monitoring pipeline functions without Grafana

  • Dashboards may need to be imported or created manually

Verify Operation

Logs

  • Fluent Bit console output shows log ingestion

  • Loki is reachable and receiving logs

Metrics

  • Prometheus UI is accessible

  • OpenTelemetry collectors expose scrape endpoints

Visualization (Optional)

  • Grafana dashboards show incoming logs and metrics

Stop the Monitoring Stack

To stop all monitoring components:

cd "C:\Monitoring Expension"
.\stop-monitoring.ps1

This cleanly shuts down all running processes started by the POC.

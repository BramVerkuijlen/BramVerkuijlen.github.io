Monitoring Expansion : Limitations

Created by Bram Verkuijlen, last modified on dec 19, 2025

OpenText Content Management server (xECM) has several inherent limitations in terms of monitoring, metrics, and tracing capabilities. Understanding these constraints is essential for designing a feasible observability approach.

Lack of Native Tracing

Unlike traditional observability systems that support agent-based trace instrumentation (e.g., OpenTelemetry Agents), OTCM does not provide:

  • Java agents for active trace collection

  • Any endpoints to push trace data externally

  • Automatic span creation

Implications

  • No native or agent-based traces can be captured

  • Traces must be reconstructed manually by correlating log files (e.g., Thread Logs, SQL Connect Logs, Web Server Client Logs)

  • Trace reconstruction can be incomplete depending on log detail and active modules

  • During the POC, no trace files or agent-generated traces were found, confirming that OTCM relies solely on logs for any trace-like information

Active tracing is not supported; only log-based trace reconstruction is possible.

Limited Metrics Collection

OTCM does not provide a central metrics endpoint. Metrics must be derived from:

  • Logs (Thread Summary Timing Logs, SQL Connect Logs, Web Server Client Timing Logs, Security Logs)

  • OTCM APIs (limited)

  • Host-level metrics (CPU, memory, disk usage) via external collectors like OpenTelemetry Collector

Implications

  • Metrics collection is fragmented and requires aggregation from multiple sources

  • Metrics are not exposed in real time; parsing of log files or event streams is needed

  • Complex dashboards or real-time alerting require custom ETL or log-forwarding setup, often via Fluent Bit or similar tools

Metrics are obtainable but require additional configuration, parsing, and aggregation; there is no built-in central metrics endpoint.

Fluent Bit Instrumentation Limitations

  • OTCM provides only a basic Fluent Bit configuration file for shipping system and security logs

  • Fluent Bit is not installed, managed, or started by OTCM; manual setup is required

  • No advanced configuration (e.g., routing, output plugins) is provided by OTCM

  • Monitoring capabilities remain limited and largely manual

Overall Observability Challenges

  • OTCM monitoring is hard and fragmented

  • No native support for modern observability patterns (traces, metrics endpoints, agent-based collection)

  • The system is largely log-driven, making automated tracing or real-time analytics difficult

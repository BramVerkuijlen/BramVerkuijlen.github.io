Purpose / Overview

Security Logs capture all access, authentication, and authorization activities within the Content Server (OTCM).

They track:

  • Which users perform which actions and whether they succeed

  • Server and request context relevant to security

  • Duration of security-related operations

  • Authentication methods and outcomes

These logs are essential for:

  • Security monitoring and auditing

  • Compliance reporting

  • Investigating security failures or anomalies

  • Performance analysis of security-sensitive requests

Security Logs include unique x-requestid values, allowing correlation with other log types for end-to-end request analysis.

Key Fields & Metrics

Field

Description / Metric

x-utc-timestamp / date / time

Timestamp of the logged action

x-threadid

Thread in which the action occurred

c-ip

IP address of the client

x-authuser / x-authusername

Authenticated user

c-func / c-method

Executed function or method

cs-uri

URI of the requested resource

time-taken

Duration of the action (ms), useful for performance analysis

bytes

Amount of data processed during the action

x-server / x-uptimems

Server name and uptime in milliseconds

x-sourcedevice

Origin of the request (e.g., OTDS)

x-authmethod / x-authstatus

Authentication method and result (success/fail)

x-requestid

Unique request ID, links to other logs for correlation

x-response

Result of the action (success/fail/etc.)

Relevance

Security Logs are usefull for understanding access, authentication, and authorization behavior.

Value

★★★★★ – Primary source for authentication and authorization errors

★★★☆☆ – Includes timing for security operations

★★★★★ – Can be linked via x-requestid to client, timing, or thread logs

Correlation

Security Logs are especially useful when correlated with:

  • Web Server Client Logs / Timing Logs – track which requests triggered authentication/authorization checks
    Web Server Client Timing Logs

  • Thread Logs / Thread Summary Timing Logs – see backend threads handling security requests
    Thread Logs Thread Summary Timing Logs

  • SQL Connect Logs – identify database queries related to security checks
    SQL Connect Logs

Observability Context

  • Logs provide full visibility into security-related activity

  • High volume: filter by x-authuser, x-requestid, or x-authstatus for analysis

  • Essential for auditing, compliance, and security troubleshooting

Purpose / Overview

Java JVM Logs capture output from specific Java classes and methods in OTCM.

These logs are primarily used for troubleshooting and debugging startup or runtime issues, rather than routine monitoring.

They can be activated or controlled via java.server.logging.properties, and typically record:

  • Start and end points of Java methods

  • Internal JVM actions

  • System or network-related information (e.g., generated host IDs, network interfaces)

These logs are not performance-oriented; they do not track request timing or system metrics.

Correlation

Java JVM Logs can potentially be cross-referenced with:

  • System Monitoring Events – JVM startup or crash events
    System Monitoring (JSON Events)

  • Thread / Timing Logs – For identifying method-level issues affecting request processing
    Thread Logs Thread Summary Timing Logs

Observability Context

  • Logs are primarily created on server startup or when specific classes are activated via configuration.

  • Useful for diagnosing method failures, class loading issues, or network interface problems during agent initialization.

  • Not suited for dashboards or real-time performance monitoring.

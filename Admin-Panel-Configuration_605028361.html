Purpose

The Admin Panel serves as the central interface to configure OTCM services, particularly logging and monitoring settings.

For this POC, this page focuses on:

  • How to navigate the Admin Panel

  • Activating or deactivating logging modules relevant for monitoring

  • Enabling Fluent Bit integration for forwarding system and security logs

  • Configuring temporary logging for troubleshooting purposes

Detailed log types, formats, and usage are covered in the Logs subpages.

Accessing the Admin Panel

The Admin Panel is available through the web browser via:

http://<OTCM-HOST>/OTCS/cs.exe?func=admin.index

  • <OTCM-HOST> should be replaced with the hostname or IP address of the machine where OTCM is running.

  • Administrator privileges are required to access the panel and make changes to log settings or other configurations.

  • In multi-node setups, always connect directly to the target node for node-specific settings (especially for Instance Log Settings).

Fluent Bit Integration

OTCM supports integration with Fluent Bit for shipping system and security logs.

Admin Panel Location:

Admin Server → Log Settings → Fluent Bit Settings

Features:

  • Forward Security Logs and System Monitoring Events via TCP (default port 5170)

  • Generates JSON-formatted events that external collectors (like Fluent Bit) can process

  • OTCM does not start or manage Fluent Bit; administrators must install, start, and configure Fluent Bit separately

POC Relevance:
Enables centralized collection of system and security logs for further processing in OpenTelemetry or other observability tools.

Instance Log Settings

Instance Log Settings allow per-service configuration for OTCM log modules.

Admin Panel Location:

Admin Server → Log Settings → Instance Log Settings

Configurable Options:

  • Enable/disable log modules for specific services

  • Set log levels (INFO, WARN, ERROR, TRACE, etc.)

  • Specify storage locations and rolling log policies

  • Configure buffering behavior and module-specific options (e.g., SOAP parameters, request details)

Note: Changes apply only to the connected node. In multi-node setups, always connect directly to the target node to apply changes correctly.

Temporary Log Settings

Temporary logging can be activated for diagnostics, troubleshooting, or short-term monitoring.

Admin Panel Location:

Admin Server → Log Settings → Temporary Log Settings

Features:

  • Expiration date automatically reverts temporary settings to defaults

  • Can be enabled for specific servers in the OTCM installation

  • Configurable log levels for SQL Connect Logs, Security Logs, and Thread Logs

Temporary logging allows capturing additional information without impacting long-term performance or storage.

System Monitoring (JSON Events)

OTCM generates System Monitoring Events for internal status and health.

Admin Panel Location:

Admin Server → System Monitoring → System Monitoring

Features:

  • Captures server and process health, resource utilization, and warnings/errors

  • Forwarded via Fluent Bit TCP listener (default port 5170) in JSON format when turned on in https://amexio-group.atlassian.net/wiki/spaces/~7120202b5ef987012e4390bd33cd0bcd1947f8/pages/605028361/Admin+Panel+Configuration#Fluent-Bit-Integration

Detailed examples are provided in System monitoring logs

Java JVM Logs

  • OTCM JVM logs exist but are not accessible through the Admin Panel.

  • Configuration is managed via the file:

OPENTEXT\OTCS\config\javaserver.logging.properties

  • Logs are stored in:

C:\OPENTEXT\OTCS\logs\otjava*.log.*

  • For the POC, JVM logs are optional and accessed via the file system, not through Admin Panel settings.

Detailed examples are provided in Java logs

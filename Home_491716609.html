Introduction

This Confluence space documents an internship research project focused on exploring the possibilities of monitoring Enterprise Content Management (ECM) systems.

The project specifically targets OpenText Content Management Server (xECM / OTCM) V24.4, running on Windows, and investigates which logs, metrics, and trace-like information can be extracted from the platform without using invasive instrumentation techniques.

This research was conducted as a final-semester internship project for Fontys University of Applied Sciences – Software Engineering (Semester 8) and was carried out at AmeXio.

Objective

The primary objective of this project is:

To gain a clear understanding of the observability and monitoring possibilities of enterprise ECM systems, using OpenText Content Management Server (xECM) as a case study.

Rather than delivering a production-ready monitoring solution, this project focuses on:

  • Discovering what data OTCM exposes

  • Understanding how that data can be collected

  • Evaluating modern observability tooling (OpenTelemetry, Fluent Bit, Prometheus, Loki and Grafana)

  • Identifying limitations and opportunities for future monitoring strategies

Project Context

OpenText Content Management Server is a complex enterprise platform that in the case of this project:

  • Runs in Windows-based environments

  • Offers limited native observability features

  • Does not support modern agent-based tracing approaches

Early in the internship, attempts were made to use Java agent–based monitoring from OpenTelemetry.
Due to technical constraints and stability issues, the project had to pivot toward an agentless observability approach, relying on:

  • Log scraping and parsing

  • API-based metrics

  • Host-level system metrics

  • Log correlation for trace reconstruction

This shift shaped the final direction of the project.

Scope

In Scope

  • Research into monitoring possibilities for enterprise ECM systems

  • Extraction of data from OTCM, including:

    • Logs (security, client, timing, system monitoring)

    • API-based metrics

    • Host/system metrics

  • Designing and implementing a Proof of Concept observability pipeline

  • Evaluating tooling such as:

    • Fluent Bit

    • OpenTelemetry Collectors

    • Prometheus, Loki, Grafana (for storage and visualization)

  • Documenting findings, limitations, and future opportunities

Out of Scope

  • Full integration with AMI (AmeXio’s current monitoring platform)
    (integration possibilities were explored conceptually)

  • Deployment on client production systems

  • Long-term maintenance or operational support

  • Linux or non-Windows operating systems

  • A fully production-grade, end-to-end monitoring pipeline
    (initially considered, later deprioritized due to time constraints)

Key Principles

  • Research-driven
    Focused on understanding capabilities, not delivering a final product.

  • Agentless monitoring
    No Java agents or application-level instrumentation required.

  • Standards-based tooling
    OpenTelemetry is used as the foundation for logs and metrics.

  • Modular design
    Components can be extended, replaced, or scaled in future research.

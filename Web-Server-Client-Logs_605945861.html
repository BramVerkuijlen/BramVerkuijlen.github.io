Purpose / Overview

Web Server Client Timing Logs capture performance and timing metrics for requests processed by the Content Server via web integrations (CGI, Servlet, IISAPI).

They record:

  • Start and end timing of requests

  • SQL-related timing metrics

  • Execution duration of server-side functions

These logs are primarily used for:

  • Performance analysis between client and server

  • Detecting slow requests or latency spikes

  • Correlation with SQL and thread metrics to understand end-to-end processing times

Because these logs wrap the request lifecycle, they provide a holistic view of request latency, including database and server-side processing.

Relevance

Web Server Client Timing Logs are critical for observability of client-server interactions.

Aspect

Value

Troubleshooting

★★★★☆ – Identify slow requests and error patterns

Correlation value

Correlation

These logs are especially useful when linked with:

  • Web Server Client Logs - for more in depth information on the proccess the timings where made of
    Web Server Client Logs

  • Thread Summary Timing Logs – to determine which server threads caused delays
    Thread Summary Timing Logs

  • Thread Logs – to identify backend errors or warnings affecting requests
    Thread Logs

  • SQL Connect Logs – to detect database-induced latency
    SQL Connect Logs

Observability Context

  • Provides direct client-side timing metrics for each request

  • High volume: filter by Request ID, Func.Action, or IP for meaningful insights

  • Essential for end-to-end performance analysis of user interactions

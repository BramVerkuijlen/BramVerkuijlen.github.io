Purpose / Overview

Web Server Client Logs provide detailed runtime information for requests sent through the web server (CGI, Servlet, IISAPI) to the Content Server.

They capture:

  • Function calls and system interactions

  • Socket-level communication

  • Request lifecycle events (sending, waiting, receiving)

  • Errors, warnings, and debug traces

These logs are primarily used for:

  • Troubleshooting functional errors in web requests

  • Monitoring socket communications and network interactions

  • Correlating execution behavior with performance metrics via Request ID

Because each request includes a unique Request ID, these logs can be directly correlated with Web Server Client Timing Logs to track both what happened and how long it took.

Configuration files and settings used by the request

Correlation

These logs are especially useful when correlated with:

  • Web Server Client Timing Logs – track the same request ID to connect execution flow and timing
    Web Server Client Timing Logs

  • Thread Summary Timing Logs – identify which server threads handled the request
    Thread Summary Timing Logs

  • Thread Logs – detect backend warnings or errors impacting the request
    Thread Logs

  • SQL Connect Logs – trace database queries triggered by the request
    SQL Connect Logs

Observability Context

  • Logs provide detailed insight into request execution, including socket-level operations

  • High volume: filter by Request ID, Component, or log level to analyze relevant requests

  • Useful for troubleshooting functional issues, network delays, or communication errors

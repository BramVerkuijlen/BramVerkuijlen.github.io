Monitoring Expansion : Loki

Created by Bram Verkuijlen, last modified on dec 29, 2025

This section documents Loki as used in the Monitoring Expansion POC. It describes its role in the observability pipeline, the configuration used, and how it integrates with other components like the Central Collector and Grafana.

The goal of this part of the documentation is not to explain Loki in detail as a logging platform, but to describe:

  • What data Loki receives in this POC

  • How Loki is configured

  • How Loki integrates with the pipeline

  • Limitations and considerations

This documentation is based on hands-on technical research performed during the internship project.

Purpose

Loki serves as the log storage backend for the observability pipeline:

  • Receives logs forwarded by the Central Collector
    Central Collector

  • Stores logs in a time-series format for efficient querying

  • Provides log data for Grafana dashboards
    Grafana

Loki does not process or transform logs; it stores and indexes logs for later retrieval.

Context

In this POC, Loki is deployed on the same Windows VM as other components for simplicity. It can also run on a separate host as long as it is network-accessible by the Central Collector.

  • Loki Version: 3.6.3

  • Operating System: Windows Server

  • Architecture: Standalone instance using filesystem storage

Loki interacts with:

  • Central Collector – receives logs via OTLP/logs export
    Central Collector

  • Grafana – visualizes logs stored in Loki
    Grafana

  • Prometheus – optionally scrapes internal Loki metrics
    Prometheus

Key Responsibilities

Loki acts as the central log storage and query engine:

  • Receives logs from OpenTelemetry Central Collector

  • Stores logs in TSDB (time-series database) format

  • Supports queries and dashboards in Grafana

  • Provides basic log-derived metrics for Prometheus

Loki does not:

  • Transform or enrich logs

  • Collect metrics other than basic internal statistics

  • Generate alerts

Architecture Role

Loki functions as the log storage layer in the observability pipeline:
Architecture

  • Positioned downstream of the Central Collector, which feeds logs

  • Logs are stored for long-term querying and visualization in Grafana

  • Pattern-based ingestion allows for metric extraction from log data

Key architectural points:

  • Centralized log storage for all telemetry

  • Provides time-series query access via Grafana

  • Scalable with replication and persistent storage in production (not configured in this POC)

Limitations and Constraints

  • No authentication enabled (auth_enabled: false) for POC simplicity

  • Uses in-memory kvstore and local filesystem; limited durability and scalability

  • Retention is not configured beyond default filesystem storage

  • Not optimized for production-scale workloads

  • Metrics and analytics reporting to Grafana Labs is optional and disabled

Configuration Overview

The Loki configuration for this POC is:

auth_enabled: false

server:
  http_listen_port: 3100

common:
  ring:
    instance_addr: 127.0.0.1
    kvstore:
      store: inmemory
  replication_factor: 1
  path_prefix: /tmp/loki

query_range:
  results_cache:
    cache:
      embedded_cache:
        enabled: true
        max_size_mb: 100

limits_config:
  volume_enabled: true
  metric_aggregation_enabled: true
  enable_multi_variant_queries: true

schema_config:
  configs:
    - from: 2020-10-24
      store: tsdb
      object_store: filesystem
      schema: v13
      index:
        prefix: index_
        period: 24h

storage_config:
  filesystem:
    directory: /tmp/loki/chunks

pattern_ingester:
  enabled: true
  metric_aggregation:
    loki_address: localhost:3100

frontend:
  encoding: protobuf

Please refer to the official documentation for more detailed information on how to further configure Loki.
https://grafana.com/docs/loki/latest/

Global Settings

  • auth_enabled: false – disables authentication for simplicity

  • server.http_listen_port: 3100 – HTTP port for Loki queries

  • common.ring – used for sharding/replication (POC uses in-memory)

  • replication_factor: 1 – single instance replication

  • path_prefix: /tmp/loki – base directory for storage

Storage & Schema

  • storage_config.filesystem.directory – where log chunks are stored (/tmp/loki/chunks)

  • schema_config – defines TSDB layout, indexing, and time-based partitioning

  • index.prefix and index.period – naming and rotation of index files

Server & Ingestion

  • Receives logs from Central Collector via OTLP/logs endpoint

  • Query cache enabled (query_range.results_cache) to improve Grafana query performance

  • limits_config enables volume metrics and multi-variant queries for log-derived metrics

Pattern Ingester

  • Enabled (pattern_ingester.enabled: true)

  • Supports log-derived metric aggregation (metric_aggregation.loki_address)

  • Allows extraction of structured metrics from unstructured logs

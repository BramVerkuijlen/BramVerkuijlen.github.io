Monitoring Expansion : Security Logs Input

Created by Bram Verkuijlen, last modified on dec 19, 2025

Config file: inputs/ot_security_logs.conf

This configuration ingests OTCM Security Logs directly from the filesystem.
Security Logs capture authentication, authorization, and access-related activity within OTCM.

Detailed log structure, field meanings, and examples are documented in the Security Logs page.

Input configuration

# Opentext security logs
# Configured in OTCM via:
# http://<OTCM-HOST>/OTCS/cs.exe?func=admin.FluentBitConfig

[INPUT]
    Name tail
    db C:\Monitoring Expension\Fluent Bit\db\securitylogs.db
    Path C:\OPENTEXT\OTCS\logs\security_logs\security*
    Path_Key file
    tag cs.securitylogs

Explanation

Setting

Explanation

Name tail

Reads log files from disk and tails them incrementally

db

State database to track read offsets across restarts

Path

Location and filename pattern of OTCM Security Logs

Path_Key file

Adds the source file path to each record

tag cs.securitylogs

Tag used to route and process security log events

Metadata enrichment filter

[FILTER]
    Name modify
    Match cs.securitylogs
    Add applicationID -
    Add applicationVersion 24.4
    Add company opentext
    Add componentCode security
    Add level INFO
    Add logger -
    Add message -
    Add server Opentext-xECM-f:2099
    Add serviceCode xecm

Explanation

This filter enriches raw security log entries with static metadata, ensuring consistency across all OTCM log streams.

Field

Purpose

applicationID / serviceCode

Identify the source application

applicationVersion

OTCM version used in the POC

company

Vendor identification

componentCode

Logical component name

server

Originating OTCM node

level / logger / message

Normalized fields for downstream processing

Parsing filter

[FILTER]
    Name parser
    Match cs.securitylogs
    Key_name log
    Parser securitylogs_parser
    Reserve_Data True

Explanation

Setting

Explanation

Key_name log

Field containing the raw log line

Parser securitylogs_parser

Applies the custom regex parser

Reserve_Data True

Keeps original fields alongside parsed values

This step converts tab-delimited security log lines into structured fields usable for metrics, filtering, and correlation.

Parser definition

Config file: parsers.conf

[PARSER]
    Name securitylogs_parser
    Format regex
    Regex ^(?<x_utc_timestamp>[^\t]+)[\t](?<date>[^\t]+)[\t](?<time>[^\t]+)[\t](?<x_threadid>[^\t]+)[\t](?<c_ip>[^\t]+)[\t](?<x_authuser>[^\t]+)[\t](?<c_func>[^\t]+)[\t](?<c_method>[^\t]+)[\t](?<cs_uri>[^\t]+)[\t](?<time_taken>[^\t]+)[\t](?<bytes>[^\t]+)[\t](?<x_server>[^\t]+)[\t](?<x_uptimems>[^\t]+)[\t](?<x_sourcedevice>[^\t]+)[\t](?<x_authmethod>[^\t]+)[\t](?<x_authstatus>[^\t]+)[\t](?<x_requestid>[^\t]+)[\t]?$
    Time_Key x_utc_timestamp
    Time_Format %Y-%m-%dT%T.%L

Explanation

Element

Purpose

Format regex

Parses non-JSON, tab-separated log lines

Named capture groups

Map directly to OTCM Security Log fields

Time_Key

Uses the UTC timestamp from the log itself

Time_Format

Matches OTCM timestamp precision
